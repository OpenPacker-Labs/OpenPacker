# Contributing and releasing

## Contract-first changes

Public PREX changes begin in `spec/prex/v1` and its JSON Schemas. Regenerate
contract outputs, repair OpenAPI/AsyncAPI, TypeScript and Rust consumers,
conformance vectors, SDK/embedded surfaces, and these references in the same
change. Do not hand-copy generated contracts or add arbitrary top-level fields;
use a declared namespaced extension container.

Implementation changes follow the repository boundary: adapters acquire
snapshots, the resolver is pure, proof checking is independent, materialization
uses immutable descriptors, and trust roles remain separate. Preserve the MIT
license and native archive bytes. A behavior branch or parser change includes
the smallest regression check that would fail without it.

## Required evidence

Before review, run `npm run verify`. It aggregates formatting, schema/contracts
and generated freshness, license checks, TypeScript lint/typecheck/build/tests,
coverage, conformance/security/integration/e2e/compat/browser/fuzz gates, Rust
format/clippy/tests, benchmarks, and the offline demo. Live public-provider and
registry interoperability stays in explicit opt-in jobs and cannot replace an
offline mandatory check.

Generate reviewed protocol goldens only after a successful production-path demo
with `npm run golden:generate`, then require `npm run golden:check` to compare
every generated byte and manifest entry without writing. Schema changes require
positive, negative, maximum-size, canonical, and round-trip vectors. Solver
fixtures require independent proof acceptance and bounded oracle agreement.
Artifact changes require corruption and safe materialization checks.
Documentation changes run the
[documentation smoke check](documentation-smoke.mjs).

## Release evidence

A release candidate must have a clean `npm ci`/locked Cargo build, all mandatory
gates, package export and clean-consumer compatibility, complete declaration
files/exports maps, schema and generated freshness, a deterministic demo index,
benchmark report, dependency/license results, release SBOM/provenance when the
CI environment supplies signing authority, and an explicit protocol/package
version decision.

Inspect packed npm artifacts before publication and retain their SHA-256,
package-lock/Cargo.lock, generated schemas, demo receipt/lockfile digests, and
CI provenance together. Publishing credentials and signatures are external
release authority; local green tests do not authorize publication. The draft
vendor media types remain provisional and must not be described as registered.
